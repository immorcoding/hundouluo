## 可编辑边界与重建

`frames.json` 保存每个角色源图中的裁切矩形、站高、锚点和动画帧名。裁切不是假设生成图具有精确网格；每个矩形通过图集预览逐帧检查。脚本保留主要不透明连通区域及较大的独立枪口闪光，清除微小邻帧碎片，统一 alpha 为 0/255。角色每张图集最多 48 个 RGBA 条目，最近邻显示；角色姿态保持共同缩放，不按每帧单独拉高。静态站高 58px；角色表情／姿态仍有生成模型带来的细节差异，不能等同于专业逐帧动画。

背景缩放至 1440×360，支柱、吊具和器材裁切后合成独立透明中景。甲板源缩放为 720×240，取顶部 108px，每 720px 延续一次，重复周期长于 640px 视口。Godot 按两段碰撞范围裁出甲板，不在 [768,864) 的真实缺口上铺图。原有黄色缺口图块继续由 `tools/legacy_pixel_art.py` 程序绘制；没有接入 #23 的素材。

运行 `python tools/build_pixel_art.py` 可离线重建全部运行 PNG、`atlas.json` 和帧预览，需要 Pillow 10+。此过程不重新请求生成模型。源 PNG 是本轮原始位图制作源，并非 SVG 或可拆开的绘画工程；如要改变机甲内部形态，可编辑该源或重新生成，再运行装配。

行动员各帧的枪口坐标保存在 `scenes/operative.tscn` 的 `muzzle_offsets`，相对角色脚底原点。改姿态后应运行 `tests/operative_muzzle.gd`，它验证可见枪管像素与站立、两帧跑动、跳跃及左向实际弹丸出生点相符。
