## 目标与验收

- [ ] 通过正式关卡普通开火输入复现并最小化两种可见症状，记录实际动作、朝向、动画帧和真实 640×360 修前画面。
- [ ] 火光的可见发光起始部位贴合当前可见枪口，不出现可感知的偏离。检查位图透明留白、可见端点、偏移和镜像，不只证明 Marker 与节点坐标相同。
- [ ] 连射时火光不反复遮盖、替换或染亮本应稳定可见的枪身主体，枪身不因效果合成产生闪烁；合理的枪口外沿发光与枪身遮盖应明确区分。用同姿态的真实合成画面/局部像素和原速循环判断，不仅断言 z_index。
- [ ] 覆盖左右站立/跑动连射、变向、起跳/落地和受击姿态，以及跟随镜头、终点固定镜头、胜利冻结、死亡/R 重试；保持已修复的运动跟随，不重新留下旧世界坐标短帧。
- [ ] 弹丸发射坐标及发出后的独立运动、碰撞、速度、射程、射速与伤害不因火光修正改变；敌方效果、残骸/行动员、门/HUD 的既有读数与层级不退化。
- [ ] 完成捕获原症状的红→绿回归、完整 Godot/Python 回归、独立 Standards/Spec 审查，保留修前/修后原生图片与明确原速短循环、真实日志和诊断记录。

## 实施流程与范围

派发后由独立实施会话先 `diagnosing-bugs`：先建立能判定可见偏移和枪身闪烁的快速红色反馈环，再最小化、提出可证伪假设、逐变量验证。随后 `/implement <本票URL>`，在已批准的真实场景公开输入/事件/实际渲染 seam 上执行 TDD；提交和推送功能分支，独立两轴 code-review。不以原 #35 已通过的纯锚点距离检查替代本票的可见合成症状。

预期最小范围是行动员的枪口效果接线、姿态/局部偏移与绘制，以及专属捕获/回归记录。通用 CombatFlash 或弹丸若需修改，先证明必要性并核对敌方和独立生成弹丸的兼容。正式关卡、版本/打包及公共验收汇总文件留协调集成，确需共享文件先报告依据，不扩展无关重构。
