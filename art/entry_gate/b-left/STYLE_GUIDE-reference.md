# 总体美术风格：未来机库像素风

适用于关卡、角色、敌人、闸门、弹丸、特效、HUD 与结算界面。此文档是跨资产的目标与审查基准；[旧版制作记录](README.md)说明 #22 的来源和当时的实现，不代表现有每张图都已达到本规范。视觉方向来自 [#7 的原创视觉决策](https://github.com/immorcoding/hundouluo/issues/7) 和用户认可的 #22 救援机库实机画面；后续反馈以 GitHub 对应设计票为准。

## 统一观感

- **整体是像素风，不只是使用低分辨率纹理。** 可辨认的像素簇、明确的阶梯轮廓和有限的局部色阶贯穿远景、近景、角色、道具、门、弹丸与 UI。避免一处是模糊绘画、另一处是锐利方格或光滑矢量的混搭。
- 逻辑画面为 **640×360**，展示窗口使用整数倍缩放和最近邻采样。审查以原生尺寸及游戏运行画面为准，放大图只辅助检查边缘；不以高分辨率概念图代替实机验收。局部纹理应与相邻资产保持接近的有效像素颗粒度，不为每种资产机械指定相同的格宽。
- 轮廓、斜线、明暗和磨损尽量用有意组织的像素块表达；不要靠模糊、渐变、半透明软边、亚像素描边、自动抗锯齿或单纯把高清图最近邻缩小来假装像素风。生成辅助的源图需要人工筛选、限色/清理和原生视口检查；工具及来源另见[源资产记录](../../assets/art_source/README.md)。
- 背景低饱和蓝灰并做景深，行动员青白偏圆，机械兵橙红偏尖，防御机甲宽厚深色；信息用青色，警示与缺口用琥珀/黄色。敌我和危险同时靠形状、运动与颜色区分，不只换色。局部高光服务可读性，不让远景细节压过人物、弹道或地面边缘。
- 甲板、柱梁、管线、闸门沿用同一工业金属结构与磨损节奏；接缝、受力路径、墙脚/门靴与甲板亮面应在同一空间关系内。HUD 的边框、枪械图、生命格、弹壳也用同源的硬边、像素簇与受控色阶，但与场景保持足够对比，不把 HUD 做成另一套光滑材质。
- 中文说明文字以清晰可读为先，不强迫中文像素字；已有 Noto Sans SC 与短数字/标签可用 Silkscreen 的决定见 [#7](https://github.com/immorcoding/hundouluo/issues/7)。字体是可读性例外，不应带出非像素风面板、图标或柔化特效。

## 制作与验收

1. 每张设计票都给出实际 **640×360** 的普通交战、危险边缘/缺口和相关状态截图；运动部件另给原速短循环。把资产放入真实关卡判断角色、弹道、门洞、警告与 HUD 的前后遮挡，而非只看裁出的单体。
2. 同时检查原生画面和整数倍放大：轮廓是否有意成簇，线宽/高光/材质颗粒是否与相邻资产协调，缩放及动画中是否出现软边、像素抖动、细线闪烁、混合分辨率或不必要的密集噪声。
3. 视觉原型保持在独立分支，附前后或同机位方案对照；用户确认设计前不接入正式关卡。工程接入时复查纹理过滤、整数定位/缩放、真实碰撞及相机下的可读性。自动资源检查不能代替原生画面的审美与动态验收。
4. 每项入包资产记录源文件、制作/生成或第三方来源、许可、改动与可重建方法；借鉴经典横版射击的节奏，但不复刻现成角色、场景、音乐或标志性画面。现有资产的来源清单见 [assets manifest](../assets-manifest.md)。

## 当前待收敛处

用户认为目前**整体像素风还不够统一**，因此以上是项目目标，不是“现状已全部达标”的声明。#27 HUD 缩小和左下对齐、#32 墙式闸门左移都应以本规范审查；现有背景、甲板、角色、弹丸及其他 UI 也要在后续集成验收中逐项看原生画面，记录具体不一致处，再按影响可读性的优先级处理。不要仅因某个原型获准，就宣称整关的像素风问题已经解决。
